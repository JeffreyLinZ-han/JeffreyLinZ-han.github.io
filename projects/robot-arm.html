6-DOF Robotic Arm

A desktop manipulator designed and assembled from the mechanism outward, with custom transmissions, STM32-based actuation, absolute joint feedback, a Python operator interface, and a MuJoCo model for kinematic testing.

System overview

One platform across mechanics, firmware, sensing, and simulation.

Open digital twin

Mechanical architecture

  • Custom 3D-printed joints with timing-belt reductions, bearing-supported shafts, and modular actuator mounts.
  • Design iterations addressed pulley ratios, belt tension, backlash, shaft support, structural stiffness, cable routing, and assembly access.
  • Actuation combines STEP/DIR-controlled joints and serially commanded servo axes on a 24 V electrical system.

Electronics and communication

  • NUCLEO-G474RE controller with separate host, servo-controller, and encoder communication paths.
  • PC-to-STM32 command and telemetry interface at 115200 baud; encoder bus at 1 Mbps.
  • Python GUI supports connection verification, joint commands, homing, live encoder state, coordinated motion, and fault reporting.
Control and software

Closed-loop behavior referenced to measured joint position.

Encoder-based joint control

Shoulder and elbow control use absolute magnetic encoders as the position authority. The firmware applies STEP/DIR pulses from final encoder error, stops inside a defined deadband, requires fresh measurements, enforces hard joint limits, and aborts an axis when commanded motion makes no meaningful progress for 12 seconds.

Debugging findings

  • Identified a signed-magnitude register decoding error that erased the sign bit and made measured angle appear to reverse around zero.
  • Added continuous sample-to-sample position accumulation, explicit RAW/POS telemetry, and safe one-sided HOME behavior near mechanical stops.
  • Reduced host telemetry load and separated command completion events from periodic state updates to avoid false GUI timeouts.

Simulation and motion

The MuJoCo model mirrors the arm's joint structure. A Python motion pipeline uses position-priority damped-least-squares inverse kinematics, deterministic multi-start search, adaptive damping, joint-limit guards, and continuity scoring. The simulated end effector can trace single-stroke handwriting paths.

Validation boundary: Python modules compile, firmware passes host-side syntax checks, the MuJoCo XML and mesh references parse, and control logic has simulation checks. The latest closed-loop firmware changes have not been physically revalidated after an encoder hardware failure.
