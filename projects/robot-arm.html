01 / System

From CAD
to control.

The project was intentionally built as a whole robot rather than a collection of separate mechanisms.

I designed and assembled W-D1 around custom 3D-printed joints, timing-belt reductions, bearings, shafts, and modular actuator mounts. The shoulder and elbow use stepper-driven reductions while the wrist uses servo actuation. An STM32 controller handles low-level motion and serial commands from a Python desktop interface.

The software stack grew alongside the hardware into a MuJoCo digital twin and trajectory pipeline. The simulation provides a place to develop kinematics, joint-space motion, and handwriting trajectories before sending commands to the physical arm.

04 / Integration

The messy
middle matters.

Before clean packaging comes integration: drivers, power, serial buses, sensors, test wiring, and the small failures that reveal how the system actually behaves.

01

Communication

Integrated stepper control, servo actuation, encoder communication, serial command parsing, and host-side control across the same prototype.

02

Encoder debugging

Traced raw angle behavior, zero references, packet interpretation, and wrap-around behavior instead of treating the sensing layer as a black box.

03

Mechanical tradeoffs

Iterated reduction ratios, belt tension, backlash, shaft support, actuator packaging, and structural stiffness under real loads.

04

Model ↔ hardware

Built the digital-twin workflow around the same joint structure so simulation, trajectory planning, and the physical arm can converge on a shared model.
